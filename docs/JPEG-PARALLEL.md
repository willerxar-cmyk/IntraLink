# Parallel portable JPEG encoding

The opt-in `jpeg-parallel` build feature enables a bounded local worker strategy inside the existing software Encoder. At initialization, select one worker when fewer than four logical CPUs are available, two at four to seven, and four at eight or more. No GPU, native codec library, additional Cargo dependency or protocol negotiation is required. Default builds retain the serial path; `jpeg-simd` remains independently selectable.

For JPEG keyframes only, split the already prepared immutable RGB canvas into horizontal strips on eight-row MCU boundaries. Every non-final strip has the same MCU count. Each worker writes an independent baseline 4:4:4 JPEG with the same approved quality, quantization and Huffman tables, using its own bounded reusable byte buffer. The final partial MCU row is handled by the normal JPEG encoder. All started workers are joined before publishing a record, including worker startup or encode failures. No remote input is passed to the generated-strip parser. Check baseline frame and scan headers, expected geometry, matching tables and byte-stuffed entropy, then assemble a single standard baseline JPEG with a DRI interval and ordered restart markers. The decoder resets its DC predictors at each boundary. The final record retains the original JPEG tag and 2 MiB limit; four strip buffers each remain bounded to 2 MiB. Failure clears the output and ends the operation rather than silently lowering quality or switching codecs. Lossless tile encoding, frame sequence, adaptive policies, local authorization, source identity and negotiated wire profiles are unchanged.

Tests compare every decoded pixel against the serial encoder for 540p, 720p and 1080p, at qualities 35, 75 and 90, using two and four strips. Verify strip buffer reuse, rejection of inconsistent generated headers and atomic oversized aggregate rejection. The existing production Decoder is used for comparisons. These generated fixtures do not constitute exhaustive JPEG conformance certification or qualification of physical remote sessions.

The local `desktop-profile-check --encoder` compares the historical Image encoder, current serial encoder, two workers and four workers on the same generated canvas (12 timed samples each, alternating forward/reverse order). It additionally instruments the production Compact encoder with separate resize/RGB, tile/compare, JPEG and complete encode measurements on changing generated frames. Instrumentation is only active in the local diagnostic, not the normal capture path. No real display capture, recording or network traffic. The separate Host diagnostic uses the configured production encoder. Record actual selected worker count, per-stage times and observed Host recommendations rather than assuming a theoretical speedup.

Build opt-in portable Windows WGC with `cargo build --locked --release -p intralink --no-default-features --features wgc-preview,jpeg-simd,jpeg-parallel,resource-monitor`. Preserve the previous serial SIMD and scalar releases. Capture requests, CPU conversion, encoder and transport are still ordered at the Host; overlapping these stages across multiple frames remains a separate design and validation task. Do not start speculative readback or change credit pacing, source closure handling or consent to obtain higher benchmark figures.
