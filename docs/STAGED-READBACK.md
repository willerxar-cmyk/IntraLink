# Bounded staged D3D11 readback experiment

## Scope and invariants

The normal Host retains the existing synchronous WGC readback and portable software codec. The explicit Windows WGC diagnostic `desktop-profile-check --staged-readback` compares a staged GPU copy with that synchronous path. It uses only an owned, labeled calm generated window, fresh authenticated loopback identities, fixed v8 Compact at 1080p60/quality 75, and the existing ordered encoder lane. No new remote mode, capture permission, wire field, NVIDIA codec, dependency, driver or global timer configuration is introduced.

The native Readback adapter separates copy submission from completion, retaining at most one pending staging resource and the exact immediate context. Geometry, format, device and context are validated before submission. The experimental path calls CopyResource and Flush once, then checks Map with D3D11_MAP_FLAG_DO_NOT_WAIT. Only DXGI_ERROR_WAS_STILL_DRAWING is treated as not ready; other errors fail closed. The synchronous path uses the same validated native boundary with blocking Map and without the experimental Flush. Successful Map is scoped by the existing Unmap guard. A second copy, retargeting or duplicate completion is rejected while appropriate; incomplete polls do not mutate the CPU destination. Driver errors after submission are terminal for that capture session.

The callback lock protects generation selection, scale submission, copy submission and each completion poll. Between polls the lock is released, permitting WGC updates to the separate latest surface. The retained generation and output dimensions describe the original submitted copy, not a newer callback; immediate-context command ordering preserves its pixels. The foreground diagnostic starts staging only after an actual authenticated demand and its capture-start grant. It owns that request until a matching result, never speculatively reading a new generation. At most one staging copy is pending, and it reserves an existing local demand; the transport's existing two-demand FIFO window and eight-record credit remain unchanged.

The foreground select loop can publish a preceding completed encoder result while the GPU copy is pending. Polls have a nominal minimum spacing of 1 ms, using the existing portable absolute-deadline wait. Windows scheduling may delay the wake; there is no busy spin or claim of microsecond scheduling. Source identity, local cancellation and known capture liveness are checked on every poll and again before publication. Generation search retains a 2 s initial/17 ms subsequent budget; after submission, completion has a separate 100 ms bound. A timed-out submitted copy fails the diagnostic, never masquerading as a no-update. The stop path drops the pending request and stops the capture session; synchronous native driver calls still have no proven hard preemption guarantee. The staged path remains diagnostic-only.

## Measurement methodology

The new command compares blocking/staged/staged/blocking, 180 records per run, same transport and calm fixture, followed by a separate full-pixel visual test of staged mode with 60 records. Normal pipeline, visual and capture-lock diagnostics retain their existing 60-record scopes. The existing full-pixel regression compares decoded RGB against each actual captured reference; the additional native geometry diagnostic checks exact synthetic RGBA bytes, rejects pending overwrite/retarget and duplicate completion, verifies staging reuse, and drops an outstanding copy before verifying recovery with a fresh native readback.

Staged interpoll wait includes wall time spent elsewhere in the foreground event loop, including potential publication of preceding results. Staged Map time is the sum of native Map call durations, not the total GPU completion delay; copy submission includes the experimental Flush. Neither is isolated GPU execution time. The staged diagnostic adds poll counts, staged interpoll timing and preserves timing sample/interval consistency checks. Compare changed frames, repeats, no-updates, total wall time and stage tails; do not infer a throughput gain merely from a lower Map call time. Record actual exit codes and repeat measurements without concurrent compilation. Do not promote the experimental path without reproducible benefit, physical authorization tests and cancellation qualification. No capture-to-photon or physical network throughput claim.
