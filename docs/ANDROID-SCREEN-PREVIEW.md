# Android read-only screen preview (preview.10)

Scope: experimental actual MediaProjection -> ImageReader -> shared Rust software media -> authenticated v12 desktop viewer. No H.264 network stream, background screen sharing, recording, discovery, relay, input control or persistent screen permission. This is an implementation candidate, not physical MediaProjection qualification.

## Operator flow

1. Independently exchange full public identities. Set Android CLIENT and Windows/Linux BASE. Use the existing local vault and diagnostic manual pairing on each side; outbound BASE stores the Android private IPv4 address and dedicated UDP port. Inbound Android stores the verified BASE identity.
2. From the unlocked Android CLIENT's specific inbound peer, choose Share screen preview (Android 12L/API 32+). Review the full BASE identity, enter the tablet's private IPv4 and chosen UDP port, enter local vault passphrase, and tap Approve peer and request screen consent. Notification permission must be enabled. Android displays its real system capture authorization; the owner must accept manually on a physical device. The preview Activity must remain foreground and focused. The entire display and visible overlays can be captured; keep private content hidden.
3. On the already paired BASE, use the ordinary local graphical terminal and existing v12 viewer, with its independent explicit viewing approval:

    intralink --vault PATH_TO_BASE_VAULT view-desktop --device android --negotiate-profile --codec compact --max-height 1080 --max-fps 60

The name android is the local peer label. Use the actual saved label. Start the viewer promptly after the Android approval; Android bounds total bind/accept/exchange time and video to 15 seconds. Choose a lower receiver ceiling (540/720 or 30 FPS) if needed. The desktop viewer is unchanged and can be used from the verified preview.8 portable Windows/Linux candidate. Stop locally or close the viewer. No auto reconnect.

## Ownership and media path

ScreenShareActivity is non-exported, displays the exact peer, keeps FLAG_SECURE while entering the secret, clears/hides the form before removing it, and only transfers a one-use in-memory approval after the OS consent returns while the Activity is resumed and focused. Pending secret expires after 60 seconds; no passphrase in Intent or saved state. Shared native registry excludes concurrent probes; ScreenShareRun and local CaptureRun UI exclude overlapping projection diagnostics. Non-exported non-sticky mediaProjection service has a separate visible notification with Stop. One worker owns projection, VirtualDisplay, ImageReader and JNI call. User Stop, focus/pause, system stop, changed content dimensions or visibility, invalid identity and failure cancel. Fresh OS consent is required again. Native bridge reopens the vault, checks CLIENT role, full pinned identity against saved inbound grant, private route, and local resource ceilings; wipes the Java password array immediately after copying and drops the Rust secret after vault load. Holds the vault lock through the session. No image surface is created before the existing authenticated QUIC v12 handshake issues actual local capture demand.

Android 12L+ uniformly fits the captured display into the negotiated fixed 16:9 surface; portrait appears centered with bars rather than stretched. This first mode does not negotiate native portrait canvas or dynamically resize an existing projection. ImageReader has at most two acquired images; acquireLatestImage discards stale queued images, validates exact RGBA geometry/crop/pixel and row stride, copies to one reusable packed direct buffer and closes native image. JNI synchronously borrows the exact direct capacity on the same worker; shared core converts into reusable RGB canvases, compares actual pixels, uses Compact absolute tile deltas and complete lossless keyframes within the existing 512 KiB budget. Local platform Bitmap JPEG fallback only when necessary, bounded to existing wire maximum; adaptive JPEG quality uses existing receipt pressure. No new observed image is NoUpdate (never Repeat); unchanged actual pixels are Repeat. Invalid geometry or frame/codec failure closes session. No native arbitrary AVC decoding. The receiver uses its existing safe software canvas and bounded JPEG path. No new permissions or dependencies.

## Acceptance

The normal APK and Instrumentation include a generated Surface/ImageReader test and local JPEG color/geometry test. Use the existing owner-selected LAN test coordinator with --direction inbound --surface (Windows example compiled with lan-fixture). Unlike the earlier native generated media fixture, this invokes the ordinary Android runScreen JNI and actual platform Surface/Canvas -> ImageReader -> native Compact path. No projection token or real screen is requested in this test. Compare exact 60 frames and all pixels with the existing Windows fixture receiver. Negative checks reject revoked grant; normal package validator checks exact JNI exports, both screen/capture components non-exported and mediaProjection type, unchanged permissions, and refuses the previous opt-in fixture native symbol. See ANDROID-LAN-ACCEPTANCE.md.

Physical actual MediaProjection and graphical Windows viewer, full consent/Stop/system-stop/rotation lifecycle, actual 60 FPS and resource/latency metrics, device-wide control and signing still require qualification. Do not auto-approve physical system capture consent. Test generated fixtures only when owner is unavailable.
