# Ordered two-demand Host pipeline

The explicit `share-desktop --pipeline --fixed-quality` option uses the existing v8 desktop wire format and negotiated fixed geometry. It is deliberately incompatible with v10/v11/v12 and adaptive JPEG quality in this first implementation. A queued raw frame cannot inherit an unobserved resolution transition. The ordinary sharing path remains unchanged. Both portable CPU capture and the existing explicit WGC capture backends are supported by the source path; only the Windows generated-window WGC diagnostic is qualified here. No protocol fallback or mandatory GPU is introduced.

## Authorization and bounds

The listener and local approval sequence remain unchanged: exact paired controller, selected display identity, interactive approval, visible local stop window, successful pinned peer and fixed v8 request. There is no capture until an authenticated local request exists. In pipeline mode a single FIFO scheduler reserves at most two local requests, including already-running, completed-but-unsent and queued demands. Each unsent demand consumes one of the existing eight receipt credit positions; it does not create new wire credit. The session record budget includes reservations. No overlap before the first changed record is sent, or after a known repeat/no-update or background-priority observation. One already-issued request may precede newly observed feedback. Subsequent issuance observes the current idle/background cadence and fixed FPS ceiling. Actual local capture starts also respect the fixed FPS interval.

Both transport responses and adaptive-free media state remain ordered. The transport only consumes the oldest response, even if a later one became ready earlier. Deadline or End discards outstanding unsent demands before the final receipt drain. The bounded request channel stays at capacity one. Two recyclable encoded transport allocations are retained at most, with existing 2 MiB payload limit. Receipt order, authentication, IO deadline and frame-count checks remain enforced.

## Local source ownership

Only the foreground owner can create the native capture, perform a readback, check local indicator/ESC and selected display identity, or publish media. The CPU lane has one stateful Encoder running on a blocking worker and at most one queued raw capture. It owns no native capture handle and sends no data to the network. Each source image is moved, not copied to a second queue; at most two captured RGBA buffers and existing bounded encoder scratch are live. The previous stateful encoder is returned after each task; the next job cannot start until the preceding result is validated and handed off by the foreground owner. Native WGC readback buffers are recycled when the result returns. Local stop cancels the transport first, discards queued raw data and joins any active encoder. A native OS call or CPU encoding already executing is not guaranteed preemptible. No source switch or speculative readback is permitted.

The local Host auto-calibration remains conservative (serial sum of capture and encode), not a pipeline throughput predictor. Do not infer sustained remote FPS from the local overlap.

## Diagnostic and release gate

`desktop-profile-check --pipeline` on Windows WGC uses a disposable owned generated dense animation window and two fresh local Iroh identities bound only to loopback. It compares the existing one-demand transport and the new two-demand transport at fixed 1080p60 Compact/quality75, using the same production CPU lane, native GPU-scale readback and actual production decoder. Exactly 60 records per run, ordered sequence/geometry and generated pixel marker checked, sent/received statistics reconciled; report native/changed/repeat/no-update counts, capture begun while encoder active, elapsed record/changed FPS, capture/encode time and media bytes. No full display, external device, persisted credential or physical network is involved. No timing-sensitive pass threshold for speedup. A failed or incomplete run is a failure, not an estimate.

Test credit reservation and first-frame rules, actual QUIC out-of-order completion and saturated credit, wrong identity, ordered exact delta base, full local lane rejection, shutdown joining and CLI conflict validation. Run locked CPU and NVIDIA workspace tests, independent scalar app tests, four strict Clippy configurations, WGC portable Release, native pipeline/retarget/geometry diagnostics. Preserve previous artifacts. Future work: adaptive transition barriers, dynamic measured worker selection, physical authorized sessions, other native capture/codec platforms and sustained performance.
