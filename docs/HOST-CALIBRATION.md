# Automatic Host capture and encode calibration

The opt-in `share-desktop --capture auto` measures a bounded generated-window workload before the local sharing approval prompt. The real display is selected and verified, but is never captured during calibration. The selected real display is verified again after calibration. No listener, remote peer, vault modification, input forwarding, image recording or remote codec permission is introduced. The default remains explicit snapshot.

On a Windows WGC build, compare snapshot, persistent WGC and WGC with D3D11 scaling; the portable build only probes snapshot. Unsupported native starts and failed capture candidates are reported explicitly. A failed local source identity, marker check, cancellation, invalid encoder output or cleanup ends calibration. Native capture calls remain synchronous and cannot be preempted while inside the driver.

Each candidate uses the same owned test window at the original requested geometry; the backend-specific output tier may be 1080, 720 or 540, bounded by the requested profile. Verify exact child PID/title, unique window identity, liveness and non-minimized state. Verify native source and readback geometry, pattern markers and changing media records. Warm up one capture and measure six steady samples including native wait and capture checks. Use the production software encoder and decoder; additionally measure a changing dense synthetic image at the observed readback size in every permitted software codec mode, checking decoded geometry and a stable color marker. The benchmark does not read actual application content. A 35-second local calibration deadline and 45-second child lifetime bound the preflight, excluding the inability to preempt native calls. Close the pattern window or focus it and press Escape to cancel.

The deterministic policy reserves 25 percent of the measured local service budget, using worst observed capture plus worst measured encoding cost. It selects the highest candidate resolution meeting min(30, requested FPS); otherwise the best feasible FPS, then resolution. Preserve the requested codec ceiling, JPEG quality and duration. A candidate cannot exceed the user ceiling. Stop measuring lower tiers once a complete higher tier meets the target. The local-only `desktop-profile-check --host` exercises the same selection path with 1080p/60 FPS and Compact/quality 75. It is distinct from receiver calibration and native hardware inventory.

Display the concrete selected backend, profile and controller before asking for explicit approval. The concrete capture backend never silently changes during sharing; any runtime initialization or capture failure ends the session. Existing v8/v10/v11/v12 wire protocols, adaptive media bounds, visible sharing indicator and cancellation are unchanged. CPU-only software encoding and decoding remain available. WGC is optional and does not require CUDA.

These are short generated-window measurements, not actual monitor capture/scan-out, device-lock behavior, physical multi-host network throughput, 1080p60 certification or qualification of native video bitstreams. The XCap window workload may differ from actual full-monitor capture. Linux X11 source support is not qualified on the current Windows machine. Use explicit backend selection if calibration cannot finish or its recommendation is unsuitable.
