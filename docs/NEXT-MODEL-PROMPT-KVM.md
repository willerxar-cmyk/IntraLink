## Product requirements — non-negotiable

A normal user should not need to know IP addresses, ports, protocols, terminal commands, key fingerprints, GPU brands or technical vocabulary to use the normal graphical workflow. The first-run wizard asks whether this device is BASE (central keyboard/mouse and display controller) or CLIENT (receives control); recommend based on actual peripherals, never silently grant a role or permission. Hybrid is an explicitly chosen additional capability. The user should be able to link devices with a QR or simple short-lived pairing flow, choose Screen only, Keyboard + mouse only, or Both, see clear local approval, connect, switch and stop. Do not confuse pairing with authorization. Implement low-friction, locally visible confirmation with pinned complete identities underneath; do not use a short code as the sole authentication factor. No mandatory cloud account, automatic public relay, forced CUDA, hidden access, unattended control, permission bypass, OS security weakening, shell or arbitrary commands.

The BASE can maintain up to eight independently authorized connected CLIENTs, choose active/inactive, arrange screens by drag and drop, open a remote screen fullscreen, switch as if attached to one machine and control the CLIENT with real mouse and keyboard. A CLIENT's local operator must also see the remote cursor. Windows/Linux/Android must interoperate. Support screen viewing and KVM-only independent of video; simultaneous view/input requires separately scoped grants and a coherent session manager. Keep local control always recoverable.
