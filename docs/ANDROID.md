# Android pairing and local encoder diagnostic candidate

The Android module is a Kotlin application backed by the shared Rust encrypted vault and authenticated QUIC probe protocol. Preview.5 qualified manual bilateral pairing, local saved-peer dashboard, revocation and foreground one-shot diagnostics. Preview.6 added an explicitly consented local MediaProjection/MediaCodec AVC encoder diagnostic. Preview.7 added local bounded Rust inspection of actual encoder output through JNI. Preview.8 added actual output MediaFormat/CSD SPS metadata and PTS interval observation. Preview.9 adds one local sync-frame request and actual post-request IDR observation; instrumentation exercises a software AVC decoder with the known generated fixture. Preview.10 implements an experimental separately consented read-only screen preview on Android 12L+ using the existing v12 Compact/JPEG viewer; the owner-approved physical screen-to-Windows preview passed. Preview.11 adds an explicit separately consented 90-second entire-display navigation mode while preserving the default 15-second foreground preview. See [ANDROID-SCREEN-PREVIEW.md](ANDROID-SCREEN-PREVIEW.md) and [ANDROID-NAVIGATION.md](ANDROID-NAVIGATION.md). Preview.12 adds measured portable dense-motion payload adaptation, reused desktop JPEG decode storage and a generated native AVC assessment. See [PORTABLE-MOTION.md](PORTABLE-MOTION.md). The native MediaTek generated stream decodes offline on CPU but is not admitted by strict v9. Wider runtime and distribution qualification remain pending. The manifest retains the same INTERNET, ACCESS_NETWORK_STATE, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PROJECTION and POST_NOTIFICATIONS permissions. No discovery, public relay, automatic connection, microphone, accessibility service, background listener or remote input is enabled.

BASE/CLIENT setup recommends a role from connected input devices but grants no authority. App-private identity, role, name and directional grants use the existing Rust vault. Passwords are entered locally, copied to bounded byte arrays and cleared after use; the UI does not save password state. Screen capture of sensitive UI is blocked and cloud/device-transfer backups exclude app data. This is not a complete security audit.

## Pair and test a connection

1. Independently exchange the complete public identities shown by IntraLink on the two devices.
2. On the BASE, select Pair a CLIENT, enter a label, the verified CLIENT identity and its numeric private IPv4 address and UDP port. On the CLIENT, select Pair a BASE and enter the verified BASE identity and a label. A directional pairing does not imply reciprocal authorization.
3. Review the complete identity and route, enter the local passphrase and explicitly approve each side. There is no network traffic during pairing. Self-pairing, duplicate peer identities/labels, invalid role directions, public addresses, DNS names, loopback addresses and invalid ports are rejected by Rust for this Android UI.
4. On the CLIENT, open the saved BASE and select Accept a diagnostic. Enter the CLIENT device's private IPv4 address and UDP port, unlock the vault, then approve the single foreground session. On the BASE, select the saved CLIENT and Test connection; approve. Existing desktop listen/connect commands use the same intralink/probe/1 protocol and can be used on the other end. The listener waits up to 120 seconds; bind and exchange have separate bounded deadlines. The displayed elapsed time is diagnostic session duration, not input or network latency.
5. Stop diagnostic or leaving the resumed Activity cancels the reservation/session; the listener is closed and the vault lock released. No auto-reconnect. A process-wide unique reservation prevents concurrent Android probes and prevents stale cancellation from affecting a newer session. UI locks on return from background. Revocation removes the local grant only. Do not expose the listener publicly or change system firewall rules merely for testing.

Only manually supplied private IPv4 routes are accepted on Android. Desktop pairing may contain other routes; Android refuses to probe such a route. A new Android application context is installed once through the documented Iroh JNI bridge and retained for process lifetime. There are no new wire messages or privileges; diagnostic grants never authorize screen or input. The current Android connection implementation is a one-shot diagnostic, not persistent multi-host workspace or Hybrid multiplexing.
## Local screen encoder diagnostic (CLIENT)

Open the CLIENT profile, select Local screen encoder diagnostic and stay on the generated motion fixture. Enable notifications explicitly if required, then press Start and review the Android screen-capture consent dialog. On API 34+, request the default display using the system MediaProjectionConfig; user consent is mandatory and vendor policy can override the selection. The local fixture Activity is non-exported and separate from the FLAG_SECURE vault UI. It contains no vault secrets.

The non-exported, non-sticky mediaProjection foreground service starts its notification before obtaining the projection. One process-local lease, one token and one VirtualDisplay. The worker owns the codec, Surface, VirtualDisplay and projection callback. Preview.7 synchronously borrows the exact direct output-buffer slice for bounded Rust Annex B NAL-type inspection; no full-frame copy, persistent image bytes, disk write, decoder or socket transmission. A finally block immediately releases each acquired codec buffer. Partial frame chains are excluded from picture observation and unsupported framing is counted, not guessed. The local test is bounded to 15 seconds after capture starts, with a bounded setup attempt policy between native calls. Stop from the Activity/notification, activity pause/focus loss, system stop, changed captured dimensions/visibility, codec error or deadline ends the session and releases resources. There is no auto-reconnect or reuse of consent. Native OS calls can hang/fail; physical cancellation and cleanup still require testing.

Choose AVC Surface encoders from the actual advertised MediaCodec capabilities. Fit portrait or landscape without upscaling, respecting hardware alignment and supported size/rate/bitrate. Try 1080/720/540 envelopes, configured 60/30/24 fps, hardware preferred but software allowed. No CUDA or GPU requirement and no claim of sustained achieved FPS. Report the selected codec, configured dimensions/rate, output-buffer count, encoded bytes and elapsed time. An empty output is a separate failure result, not successful video.

The framework-only API 26+ app intentionally uses narrowly scoped Kotlin deprecation annotations for the platform consent-result/request and pre-33 Parcelable accessor paths. No Android Lint issue is suppressed. Follow the official MediaProjection guide: https://developer.android.com/media/grow/media-projection. The local diagnostic does not establish compatibility with the existing desktop media wire protocol; receiving/decoding and authenticated remote screen sessions are separate work.

## Build

Use JDK 21, Gradle wrapper 9.3.1, AGP 9.1.0, Android SDK 36, build tools 36.0.0, NDK 28.2.13676358 and Rust 1.96.0 with targets aarch64-linux-android and x86_64-linux-android. Configure ANDROID_HOME and an isolated CARGO_TARGET_DIR if needed. From the repository root on Windows:

    python tools/build_android_native.py apps/android/app/build/generated/jniLibs --clippy
    apps\android\gradlew.bat -p apps/android :app:assembleDebug :app:assembleRelease :app:bundleRelease :app:assembleDebugAndroidTest :app:lintDebug :app:writeRuntimeDependencyInventory

On Linux use python3 and apps/android/gradlew. The Gradle variant API wires the actual native outputs into packaging. The build-only Android bridge is included in the locked Rust workspace; existing registry versions were not changed. Both ABIs use API 26 and NDK r28's 16 KiB-compatible ELF segments.

Release signing is optional for building candidates; never use the debug key as a release key. Configure all four environment variables with an existing authorized keystore and its real credentials: INTRALINK_ANDROID_KEYSTORE, INTRALINK_ANDROID_STORE_PASSWORD, INTRALINK_ANDROID_KEY_ALIAS, INTRALINK_ANDROID_KEY_PASSWORD. Partial configuration fails. Do not commit any secrets, paste passwords in logs, or overwrite an existing key. Without them, release APK and AAB remain unsigned.

Generate the exact native and JVM runtime notices from the resolved build:

    python tools/release_inventory.py dist/android-arm64-notices.zip --platform android-arm64
    python tools/release_inventory.py dist/android-x86_64-notices.zip --platform android-x86_64
    python tools/android_jvm_notices.py apps/android/app/build/reports/runtime-dependencies.json dist/android-jvm-notices.zip
    python -B tools/validate_android_candidate.py dist/android-capture-candidate --notices dist/android-arm64-notices.zip dist/android-x86_64-notices.zip dist/android-jvm-notices.zip

The validator checks the archive contents, actual generated and packaged JNI export sets, ELF architecture and 16 KiB LOAD alignment, APK package/version, exact network/foreground capture/notification permission set and non-exported capture components, zipalign, test/debug signatures and release signature consistency. It retains hashes and the license inventories. The candidate gate records the remaining Gradle version advisory; no lint suppression. Use --require-signed for an authorized release candidate with no outstanding lint diagnostics; a native device acceptance gate and license review are still mandatory. The independent review markers in license manifests are not a declaration of legal compliance.

## Physical acceptance

Use an owner-authorized Android device or an emulator with a clean test profile. The debug and instrumentation APKs are for local testing only. The instrumentation runner creates disposable app-private vaults, exercises JNI identity creation, rejection of duplicate and wrong password operations, rename, role transition, reopening, manual pairing/revocation and cancellation before a diagnostic can start, then removes its test files. It does not open a real network listener or MediaProjection. It also exercises capture profile geometry and the process-local lease. Host JVM pure-policy tests: python -B tools/check_android_capture_host.py after Kotlin build and runtime inventory. Run only after confirming the selected target:

    adb -s DEVICE_SERIAL install path/to/intralink-android-capture-debug.apk
    adb -s DEVICE_SERIAL install path/to/intralink-android-capture-instrumentation.apk
    adb -s DEVICE_SERIAL shell am instrument -w org.intralink.android.test/org.intralink.android.OnboardingInstrumentation

Require the PASSED marker and successful result. Separately exercise first-run UI, app stop/restart, device rotation, wrong passphrase, role change and rename on a disposable local profile. Verify no unexpected permission requests, access outside the app or automatic connections. With two distinct authorized devices on a private LAN, test actual Windows/Linux to Android and Android to Windows/Linux probe directions, pinned-ID mismatch, revoked pairing, unavailable route, Stop, activity pause and process exit. Inspect actual endpoint closure and network egress; do not infer physical acceptance from host loopback tests. Do not use a real user's vault for tests. Preview.6 and preview.7 JNI instrumentation executed on the dedicated API 36 x86_64 emulator. Preview.9 also passed actual JNI and software decoder instrumentation on the owner-authorized physical ARM64 TB373FU; physical MediaProjection, vendor encoding and general device compatibility remain unqualified. Separately run the real local capture test on an authorized device, explicitly approve/deny system consent, verify actual buffers and measured throughput, test Stop, activity focus/pause, system stop, rotation/resize, permission denial, software fallback and resource release. Do not capture sensitive content; no physical encoder result is inferred from JVM or packaging tests.

Physical LAN acceptance tooling and real Windows/Android results are documented in [ANDROID-LAN-ACCEPTANCE.md](ANDROID-LAN-ACCEPTANCE.md). The opt-in generated media fixture native symbol is excluded from ordinary candidates.

## Preview.7 local encoder-to-Rust bridge

The direct-buffer JNI boundary validates explicit framing, exact capacity, non-null address and the existing 2 MiB access-unit limit. Rust inspects up to 32 NAL descriptors on the stack; only a numeric type mask crosses back into Kotlin. The sole codec worker owns the buffer until the call returns. No pointer or image content escapes the call. Generic NAL observation is not a v9 profile validation, picture-boundary proof or decode security guarantee. No new permissions or wire messages.

The UI separates configured FPS, total output buffers, VCL-containing complete-flagged buffers per elapsed second, IDR, codec config, partial chains, unsupported/unparsed buffers, IDR/key-flag differences and non-increasing PTS. Those are observations rather than presentation FPS or end-to-end latency. The existing local consent and 15 s deadline remain mandatory.

On a freshly installed, owner-authorized **disposable emulator only**, execute the real system consent UI acceptance script:

    python -B -u tools/verify_android_capture_emulator.py --serial emulator-5562 --avd IntraLink_API36_Test

The script verifies exact AVD name and qemu identity, never uses a physical target, creates only a disposable CLIENT, clicks the actual system permission/consent UI, and checks projection/service closure after denial, completion and Stop. It expects English UI and a fresh app install. It exports no screenshots or encoded buffers. The script is not a bypass of platform permission or a physical runtime certification. Use an isolated AVD home and do not reuse a personal Android profile.

## Preview.8 output format and cadence observations

On actual INFO_OUTPUT_FORMAT_CHANGED, the codec owner reads reported dimensions/profile/level/color fields and the Android Annex B csd-0/csd-1 buffers. Unknown numeric fields are -1. Only small CSD buffers up to 1032 bytes may be copied from heap into direct memory; no coded picture is copied or retained. Shared Rust SPS prefix parser observes Baseline/Main/High progressive 8-bit 4:2:0, level, visible orientation geometry, reference count and POC type (0/2). Returns packed numeric metadata through the same borrowed JNI boundary. It is not full SPS/PPS or VUI validation and cannot qualify native decoding. A duplicate/unsupported SPS is unavailable, never guessed. Color fields come from MediaFormat and are not inferred from SPS.

Picture-buffer PTS measurements report nonnegative increasing high-water span and min/max interval among observed buffers. Invalid/non-increasing timestamps are counted and excluded from interval calculations. Wall-clock buffer rate, configured FPS and PTS cadence are distinct; no presentation rate claim. The emulator acceptance script now requires observed SPS dimensions to match configured geometry, SPS/PPS headers, positive PTS intervals, and the existing system denial/completion/Stop gates. See AVC-PRODUCER.md. Remote Android media authorization, actual producer/decoder negotiation and decoder isolation remain separate implementation work.

## Preview.9 sync-frame and decoder qualification

The local diagnostic requests one sync frame via MediaCodec.setParameters(PARAMETER_KEY_REQUEST_SYNC_FRAME) after seeing an IDR and two dependent pictures and draining available output. Only the owner thread requests it. A subsequent complete matching IDR with strictly newer PTS within 2 seconds is observed, not assumed to be caused by the request (a naturally scheduled IDR may coincide). Numeric diagnostic states are 0 waiting, 1 requested, 2 observed, 3 rejected, 4 expired. No retries, frame retention, or remote recovery control. Cancellation is also checked inside the bounded drain loop.

The instrumentation-only AvcDecoderFixture uses exactly the hash-pinned generated 1080p AVC fixture. A declared software MediaCodec decoder decodes all six original units and the four-unit subset after dropping two dependent pictures and restarting at the next IDR. Verify visible dimensions/crop, ordered timestamps, bounded plane strides/buffer access, sampled colors and equal full visible planar YUV hashes for each retained frame. The fixture is packaged only in the instrumentation APK and verified by the candidate validator; not an app runtime decoder or arbitrary remote bitstream admission. No actual on-screen presentation or physical hardware qualification is implied. See AVC-NEGOTIATION.md for the separate loopback agreement experiment.
