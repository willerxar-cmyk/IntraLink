# Authenticated AVC operating-point negotiation diagnostic

Status: implemented and tested in shared Rust core and real Iroh QUIC loopback; no app or LAN media session enabled.

The separate ALPN intralink/avc-negotiation/1 has one bounded offer per endpoint. Producer is the CLIENT encoder and receiver the BASE decoder for the intended screen-view use case; these protocol roles are not identity/vault privileges. Both applications must independently authorize the exact local peer and operating-point list before a negotiation. Current API is an explicit one-shot diagnostic only. It binds and connects loopback sockets only, rejects unexpected TLS endpoint identities and never starts any capture or decoder. The existing v9 AVC, desktop software and input protocols remain unchanged.

## Canonical records

Fixed 272-byte offer: 16-byte header (magic/version, role, count, independent geometry/FPS/bitrate ceiling, zero reserved byte), up to sixteen 16-byte exact modes and all-zero unused slots. Each mode contains orientation-specific visible width/height, AVC profile/level/constraints, reference count, POC type, explicit color enum, FPS, zero reserved byte and bitrate. Core constructors enforce bounds, no duplicate/empty offers, all modes within local ceiling. Decoder rejects invalid lengths, flags, values and padding. This represents local prequalified operating points, not untrusted proof of actual decoder capacity.

The receiver sends its offer; the producer returns its own canonical offer and exact selected mode (288 bytes). Receiver independently recomputes the intersection using the original local offer and echoes the entire response with FIN. Producer compares all bytes and requires bounded end-of-stream before returning completion. Receiver requires exact completion and FIN. No media records, commands, arbitrary payloads or implicit fallback. The result does not authorize a subsequent connection. Deadlines are 20 s accept, existing 10 s TLS connection limit and 5 s exchange; close on invalid identity, no common mode, invalid or trailing data, timeout. There is no persistence, discovery or relay.

Tests: core canonical round-trip, portrait selection, truncations, invalid fields, duplicate/padding/outside limits; real QUIC pinned identities and exact portrait intersection, unapproved identity/nonloopback rejection, no common mode rejection and altered/trailing confirmation rejection. Final core 117, transport 66, multi-host 3 passed, strict Clippy. This is not a native codec interoperability test or a complete LAN screen capability. Future media sessions need an independent local consent binding, complete decoder admission/containment and an approved operating point established by real codec qualification, including actual color and geometry.
