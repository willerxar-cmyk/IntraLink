# Visual fidelity and recognizable local diagnostics

The earlier pipeline comparison presented a large generated high-entropy image that alternated RGB values rapidly. That visible test content can resemble a corrupt remote desktop even when the decoder is functioning correctly. The reported visual symptom is therefore not, by itself, evidence of a production codec failure. The new pipeline diagnostic removes that visible dense pattern; worst-case dense JPEG fixtures remain generated in memory and are never presented by this path.

The owned test window now displays a labeled neutral document/chart scene with four small, fixed muted red/green/blue/gray reference cards. Only the localized chart detail and progress/cursor move. The header explicitly says INTRALINK - LOCAL IMAGE TEST, GENERATED CONTENT / ESC TO CLOSE and LOCAL DIAGNOSTIC - NOT A REMOTE DESKTOP. The standard low-complexity quadrant/static/geometry fixtures remain unchanged. The child remains disposable, selected by exact PID/title and unique native identity, with bounded lifetime and cancellation. No arbitrary application or real monitor capture is introduced.

## Full-image qualification

On the Windows WGC portable build, run `desktop-profile-check --visual`. It uses the same one-demand and two-demand local QUIC test paths as `--pipeline`, but adds a separate validation-only reference channel. For each changed record the foreground diagnostic normalizes the actual captured image into RGB using the approved 1080p canvas, associates the exact record sequence and codec tag, and places it in a local bounded reference queue (capacity eight, no wire change). The receiving production decoder checks sequence, geometry, four color markers, and every pixel against that captured reference. References are not written to disk or sent outside the local process. All changed records must have an associated checked reference and reconciled sender/receiver counts. Repeat/no-update records retain their existing semantics.

A lossless keyframe requires exact equality. For the calm generated scene at JPEG quality 75, the per-frame maximum channel mean absolute error must be at most 6 intensity levels (0-255), worst 32x32 block mean absolute error at most 24, and the fraction of pixels with any channel error greater than 48 at most 1%. These are scene-specific diagnostic tolerances, not a universal visual guarantee for arbitrary lossy JPEG content. The comparison detects local block corruption even when fixed reference cards are unaffected. Unit tests deliberately introduce swapped color channels, a damaged block and a lossless mismatch. A visual mismatch fails the diagnostic rather than silently accepting it.

The ordinary `desktop-profile-check --pipeline` now uses the calmer scene and four native/decoded color markers without the full-reference instrumentation. The new workload differs from earlier dense-window comparisons; its FPS cannot be directly compared to those results. `--visual` is not a speed benchmark. No encoder, decoder, wire format, authorization, GPU requirement or production sharing policy is modified by this diagnostic correction. A physical authorized remote session and actual remote presentation remain separate qualification tasks. If a user still observes color corruption in a real session, preserve the exact backend, negotiated profile, serial/parallel setting and local reproduction; do not infer the cause from the prior synthetic pattern.
